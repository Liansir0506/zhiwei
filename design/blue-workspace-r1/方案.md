# 智维平台蓝色界面改版方案

版本 R1 · 2026-10-21 · 供设计评审与后续分批实施。

本轮交付为设计方案及离线交互稿，不覆盖static、不切换服务、不调用接口或模型。交互稿的数据、回答和状态均为界面示意，不作为现有功能验收证据。

## 设计方向

保留蓝色主调，采用深海军蓝导航、雾蓝灰背景、白色内容面板和克制的品牌蓝。用版式、字号、留白与动作层级体现精致感。动效帮助解释状态与空间关系，不靠大面积渐变、数字滚动或常驻闪动制造热闹。

当前要解决的具体问题：

1. 页面虽有统一圆角和颜色，但不同模块仍是独立面板叠加；长说明、空卡片和同权重按钮让主次不清楚。
2. 查询页把输入、计划、执行、五类统计堆在一屏，未生成计划时也预留空区和不可用按钮。
3. 告警详情把概况、近期告警、操作条、处置、工单和诊断历史连续铺开；用户需要先理解实现结构才能操作。
4. 上传、审核、候选、门禁、发布的内部术语混入普通操作，当前状态与下一步不够突出。
5. 现有CSS确有切页、卡片、图表和弹窗动效，但节奏分散，操作后的变化不够直观。应统一动效系统，而非只加更多动画。

## 页面结构

```text
全局导航 216/232px │ 全局顶栏 68px：位置 / 搜索 / 通知 / 账号
                  ├─ 页面头：标题 + 一句说明 + 一个主操作
                  ├─ 本页页签 / 筛选
                  └─ 主任务内容
```

全局导航在切页、开详情、展开知识页签和长会话时保持不动。只有正文、局部列表和独立详情区滚动；短摘要详情用抽屉，长流程详情有独立地址及全屏入口。会话列表属于问答页，证据栏属于回答，均不改变全局顶栏。

主导航建议为5项：工作台、告警与工单、智能问答、数据查询、知识库。设备与诊断任务放在告警与工单子页签，仍提供全局“新建诊断”快捷动作；运行、权限、评测、集成保留在管理入口，实验室放开发工具。权限仍由现有能力决定，不因设计稿扩大角色。

## 每页怎样简化

### 工作台

先展示“我的待办”和快速进入处理。顶部只留4个指标，每个有一个明确去向。中间为待处理列表与短趋势，弱化大横幅、装饰拓扑和重复数字。默认使用一致的场景窗口，读取时间和事件时间分别标注。

首屏回答：有哪些事、哪件最急、点哪里继续。演示导览移帮助菜单，不与日常主操作竞争。

### 告警与工单

子页签：告警、工单、设备、诊断任务。筛选默认为“未处理/我的待办”，关键词框加一个筛选按钮，不将全部字段平铺。列表优先展示名称/对象、级别、处理阶段、负责人和时间；完整ID移入详情或复制菜单。

点击列表先开右侧摘要，可“查看完整详情”。告警处置按“核对事件→诊断建议→创建/关联工单→处理与验证”组织，当前阶段只突出一个主按钮；上一步结果折叠成摘要，历史始终可展开。观察失败回到处理，缺证据停留补充，驳回不能误记确认。

工单同样按状态突出认领、提交回执、验证、关闭中的一个动作。上游告警状态与应用处置状态分别标注，避免“已清除”和“待确认”挤在一处却没有解释。

### 智能问答

新会话空态只留一句引导、3个示例和输入框；不展示空引用卡片、空请求详情和多段版本说明。历史从页头打开会话列表。问题提交后，示例收起，正文区域保留合理阅读宽度。

回答末尾展示来源数量、反馈、复制和相关下一步。点击来源才展开证据抽屉，窄桌面不常驻第三列。输入时保留问题草稿；加载显示具体阶段，失败保留问题并给手动重试；“复制”“已保存”就地反馈。技术详情放菜单。

### 数据查询

切成“常用统计 / 自定义查询”两个本页页签，避免同时展示两种任务。

常用统计：指标、时间范围、趋势和看明细为主；计算公式和分母从信息按钮展开，不能去掉。自定义查询：输入→生成人话条件摘要→确认并查询→结果与导出。保留现有受控两阶段执行，生成前不展示空计划框和执行按钮。

将“解析为查询计划”改为“生成查询”，“执行查询（只读）”改为“确认并查询”；计划显示对象、时间、状态、范围与条数，可修改后重新核对。未支持的需求给出可用替代，不展示空对象错误。

### 知识库

子页签：知识浏览、上传资料、待处理问题、版本发布。技术候选、Worker、绑定、哈希进入管理员详情，首屏用用户能理解的状态与动作。

上传流程：选择文件→核对内容与范围→提交审核→查看结果。后端仍需显式兼容候选与具体准入；可以自动选择已有兼容候选或提供简洁的新建引导，但不能自动批准新正文。新资料暂存后准确显示“待审核”，绝不能显示“已入库”。

问题单：原问题、修复资料、新旧回答对比、复测结果、确认解决形成一条时间线。版本页以当前可用版本、待发布项和有效下一步为主，复杂发布/回滚细节折叠，风险动作仍保留确认。

案例：审核通过后提供“导出原文”和“转交资料入库”；若后续实现直接创建暂存候选，必须保留来源与审核关系，并继续走准入，不以按钮动效代替实际入库。

### 管理入口

运行状态聚焦异常与恢复；评测先展示当前版本的结果、范围与缺口；权限先列表后签发；集成只展示状态与最近同步。普通用户不显示无权限空面板，管理员真实入口保留。实验室、接口文档、技术配置不进入普通任务首屏。

## 文案转换

|当前表达|建议表达|保留的信息|
|---|---|---|
|解析为查询计划|生成查询|执行前仍需确认范围|
|执行查询（只读）|确认并查询|只读边界在摘要旁展示|
|scope、run、manifest、candidate|范围、诊断记录、版本信息、待发布版本|完整字段仍可在详情查看|
|正式确认到告警|确认并继续处理|展示将关联哪条告警、哪次诊断|
|待审与缺口|待处理问题|资料审核与问题修复可分本页页签|
|查看内容与来源|查看原文|每次仍重新鉴权|

避免所有按钮都叫“确认”：使用“提交审核”“创建工单”“提交验证”“关闭工单”，使用户知道会发生什么。

## 动效系统

|场景|规格|目的|
|---|---|---|
|导航选中|140–180ms颜色与选中块移动|解释当前位置；不移动导航容器|
|页面切换|160–200ms淡入+最多4px位移；首屏内容立即出现|建立连续感，避免整页长时间错峰渐显|
|详情抽屉|220–260ms滑入；遮罩160ms|保留列表与详情的空间关系|
|折叠内容|160–200ms高度/透明度|说明展开与收起关系|
|查询/上传步骤|180–220ms步骤连接线和摘要切换|突出当前阶段与完成结果|
|按钮反馈|100–140ms颜色、按下1px；提交中显示loading并防重复|给出动作已被接收的反馈|
|成功/失败|成功图标180ms；Toast停留2.5–4秒；错误保留在控件旁|确认结果，不靠弹窗打断|
|加载|短任务延迟约200ms再显示骨架，避免闪屏；长任务展示真实阶段/等待|不编造百分比和实时进度|
|图表|首次进入300–450ms，切筛选只更新数据|强调数据变化，禁止每次刷新重播数字滚动|

统一使用cubic-bezier(.2,.8,.2,1)。悬停效果仅支持鼠标时启用；完整支持prefers-reduced-motion。背景不持续漂浮、闪烁或脉冲；动画不能挡住按钮、改变表格列宽、清空焦点或阻塞输入。动效多一些，阅读和操作仍需立即可用。

[交互预览](preview.html)包括工作台、告警与工单、智能问答、数据查询、知识库5个页面。可体验：导航切换、列表详情/处置步骤、问答示意与来源、查询确认、上传步骤和轻提示。

## 实施顺序与工作量边界

|批次|范围|完成标准|
|---|---|---|
|P0 设计基线|新tokens、字体、图标、按钮、表格、详情容器、固定外壳|1280/1440/1920及390下无跳变；不继续新增CSS覆盖层|
|P1 主业务|工作台、告警/工单详情与诊断、问答|用户从待办到诊断、处理、验证有清楚下一步；原状态机不变|
|P2 信息任务|查询、知识上传/问题单/版本、管理页|主操作清楚；无空计划、重复统计、技术字段占首屏|
|P3 体验收尾|统一动效、键盘焦点、窄屏、加载错误及回归|真实接口验收通过；动效不影响数据、权限、输入及返回状态|

P0先建立共享组件并迁移旧规则，逐步删去重复的index内联样式与历史补丁，不新增第N层important覆盖。复用当前FastAPI/静态前端，不为设计改版引入新框架。估时需要按最终范围和当前代码变更量拆任务，不在方案中承诺未经验证的固定工期。

## 验收标准

- 切页后侧栏/顶栏尺寸不变；打开详情、历史、引用也不变。
- 每个阶段最多一个高强调主操作；普通列表不要求用户先理解内部ID或候选绑定。
- 当前范围、结果和下一步在首屏清楚可见；技术说明不覆盖主流程。
- 所有示例、筛选、返回、关闭、取消都产生合理反馈，原输入和条件可恢复。
- 观察失败不能关闭，驳回不能算确认，新资料未审核不能启用。
- 日期/单位/分母一致，统计明细同范围，演示时间与读取时间有区分。
- 全流程可用键盘完成；抽屉关闭恢复焦点；减少动态效果后依然完整可用。
- 最后用真实接口验收成功、缺条件、无数据、失败、取消、返回、重试与刷新恢复，不能只验收截图。
