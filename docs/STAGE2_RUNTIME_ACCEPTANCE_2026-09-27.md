# 阶段 2：自动追问与 HTTP／浏览器核心验收

日期：2026-09-27。核心功能验收，不代表生产上线或 DeepSeek 生成质量验收。旧 ACTIVE、原始资料、真值、原 Hit@5 0.827 均未改变；候选未发布，流程能力仍默认关闭。

## 1. 自动追问

- 在已支持的沙箱 SOP 场景中识别设备类型、Lab 软件版本及正向观测条件。只对相关、权限允许、步骤完整且具备原文安全依据的来源追问；不将缺审批/回滚、缺原文、无权限、低分或未知版本当作用户缺条件。
- 多个适用分支同时出现时，先强一致复核相应来源，至少两种有效条件成立才追问实际观测分支；不直接选一个原因。
- 问答同步及流式均返回 `NEEDS_CLARIFICATION`，不调用 DeepSeek、引用为空。澄清结果通过请求内返回值传递，不用共享可变状态，以免不同用户互相串状态。
- 只读证据接口也区分真正追问与 `NO_EVIDENCE`；纠正此前所有流程失败都标 NEEDS_CLARIFICATION 的过宽口径。
- 支持范围是已有 Lab-YYYY.MM 与 AMF/SMF/NRF/UPF/PCF/UDM/AUSF/NSSF 场景，不是通用设备型号识别或复杂实体理解。用户需在下一轮重述包含完整条件的问题；没有自动填槽、多轮动作执行或审批代理。

## 2. 实际 HTTP 与浏览器验收

启动独立本机 FastAPI 进程、随机端口及自身随机 STAGED 集合，使用真实 MySQL、Milvus 和临时 API Key；不使用默认 header 假装完成认证。主项目或其他服务不被替换。

验证：

1. 原文 GET 无 Key 为 401；其他租户有效 Key 为 404；正确 Key 返回内容和 no-store。
2. 撤回向量行后原引用 GET 为 404，版本仍 STAGED。
3. 使用机器已有 Edge 和 Node 原生 CDP，创建独立临时浏览器目录，无需安装浏览器包，不触碰日常浏览器配置。
4. 实际页面展开三种位置标签、显示来源修订与模拟标识；流程按钮展开真实子引用中的各步骤。关闭并更换为无效 Key 后重开，旧正文被清除，显示认证失败。
5. 保存页面截图 `.runtime/test/reports/evidence-browser-20260927.png`，人工检查布局与三种标签。生成回答为明确标记的测试内容，不是调用 DeepSeek 获得的答案。

浏览器测试的三格式位置为显式测试夹具，**真实 Markdown/PDF/DOCX 文件解析、tokenizer 及位置持久化由另一项三格式真实入库测试验证**；两项测试组成分层证据，不宣称已经把三个原文件通过真实生成模型串成同一次回答端到端。流程浏览器夹具是明确模拟的完整 SOP，不是生产操作票。

首次本地就绪轮询没有整体时限，中止后按精确身份清理其随机集合、版本、两个临时 Key 与三条位置记录；这些仅为临时测试夹具，不能恢复且无需恢复。随后为测试客户端禁用环境代理并增加 25 秒就绪上限，重新通过。未删除旧业务库、集合、卷或用户浏览器数据。

## 3. 回归与剩余事项

最终全部单元以及流程源读取、三格式入库、定向领取、任务和真实 HTTP／Edge 五类针对性集成：**401 passed，0 failed，0 skipped，108.778 秒**，12 条既有依赖弃用警告。产物 `.runtime/test/reports/stage2-clarification-browser-final.xml`；不是全部 API/业务集成或压力测试。真实本地 tokenizer、同步/流式终态、澄清不调用模型、权限失败不追问、未知版本和分支歧义均有测试。流程浏览器断言首次不兼容归一化后的半角冒号，修正测试后整套重跑通过，未放宽业务权限。
