## 后续按顺序执行的闸门

1. **来源准入**：人工核对 RFC 原文与勘误、摘要事实、适用前提和非生产边界；按 2010/2011 年发布时适用的 IETF 许可条款与本地演示用途核对。记录实际审核人、依据、日期和最终卡片哈希；不能让 AI 草稿作者冒充独立审核人。未过关保持 pending，不注册、不入库。
2. **知识范围与独立性**：核对旧知识正文、同义概念和开发笔记，画出按 RFC/正文族/主题/模板/来源 ID 的关联组。BFD 与 NETCONF 仅作为两个候选来源组；若要评价平台整体检索质量，还需另获多个真实差异化、可合法使用的来源组，而非同卡改写。只读检查无精确术语碰撞不等于此项通过。
3. **隔离演示准备**：来源通过后，另行授权在隔离 STAGED 版本注册/索引；明确 `tenant_id`、可见角色、设备/版本适用范围、撤回路径。现阶段不将两卡写入旧 ACTIVE 库；若只是静态本地讲解，甚至不需要入库。
4. **评测题与真值**：仅在来源已批准且用途明确后，由未参与检索调参的审核流程拟题，并依据批准原文的行号/条件独立标注；按来源连通组整体切分，记录 `development_exposed`。权限、拒答、澄清路径单列分母。所有题先 pending，人工批准前不得跑正式指标。
5. **冻结与一次性验收**：固定来源正文、索引版本、权限、题集、标签、检索代码与参数哈希。开发只用 dev；frozen 在最后一次显式运行并记录分母、Hit@5、MRR、必要证据覆盖、拒答/权限和引用支持性。若题目被用于调阈值、修 bug 或演示答题，整组降为 dev，不能“重新冻结”。
